# Target Operating Model

## Operating Principles
1. One source of truth for weekly KPIs.
2. Every critical control has one accountable owner.
3. Exceptions are visible before the weekly review.
4. Leading indicators trigger action before lagging KPIs fail.
5. Labor decisions use service guardrails.
6. Improvements are standardized before project close.

## Daily Rhythm
**Pre-open:** readiness checklist, staffing gaps, priority tasks, high-risk inventory items.
**Midday:** labor vs plan, queue threshold review, task progress.
**Peak periods:** active queue monitoring and backup coverage triggers.
**Close:** unresolved tasks, cash/inventory exceptions, next-day risks.

## Weekly Rhythm
Monday: prior-week data validation.
Tuesday: workstream root-cause review.
Wednesday: corrective action execution.
Thursday: risk/dependency follow-up.
Friday: operating review and decisions.

## Escalation Logic
- Red KPI + no recovery plan → sponsor escalation.
- High risk score (15+) → mitigation reviewed weekly.
- Action >7 days overdue → sponsor visibility.
- Data-quality critical error → dashboard publication paused.
- Labor improvement accompanied by NPS/wait deterioration → staffing decision reopened.

## Management Artifacts
Executive dashboard, action plan, risk register, RACI, control log, decision log and SOPs form the minimum operating system.
